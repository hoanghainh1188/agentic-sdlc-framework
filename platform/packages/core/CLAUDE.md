# CLAUDE.md — Core: workflow, gates, evaluations, evidence, data

Rules for `platform/packages/core`, the worker that runs its loops and workflows (`platform/apps/worker`), and their tests. The root `CLAUDE.md` still applies. Never break a rule here; the detail is in the linked ADR. Each rule ends with its IDs in `design/RULES.md` (ADR-M84).

## Workflow and gates
- The database is the source of truth: `stepIntent` makes at most one move under the intent lock (compare-and-set, audit event and notice in one transaction). Workflow code imports only `@temporalio/workflow`, `@sdlc/contracts` and activity types (ADR-M30). [R043]
- No Temporal timer for escalation clocks: they live in the `escalations` row (ADR-M28). The gate deadline is the workflow's only timer. Escalation clocks, retention, spend sync: plain worker loops, never Temporal schedules. [R044]
- Call `assertActionAllowed` before a protected action and `revalidateEscalationDecision` before acting on a decision; `kill_run` and `revoke_credentials` are never frozen. A budget goes up only by a decision that names `budget_increase` with an amount (API or CLI), never by a comment; budgets only go up (ADR-M28, ADR-M34). [R045]
- Never start a run while `hotlBlockWindowOpenUntil` returns a time (ADR-M30 §2.4b). [R046]
- Every step and `waiting_for` resolve oversight through `resolveGateOversight`: never call `policy.oversightMode` in a step module (ADR-M54). Never compute a waiting reason outside the step; a new reason or cause needs its `IntentWaitReason`, catalog label, `api-schemas` map and `sdlc next` rule (`REASON_RULES`, `CAUSE_RULES`) (ADR-M54 §2.4b). [R047]
- G2 passes only with ≥ 1 acceptance criterion, at every tier (ADR-M61). Specs and plans are read from the default branch; only hashes, counts and codes are stored, never their text (ADR-M39, ADR-M40). [R048]
- Never store a new plan version automatically: a changed plan file holds G3/G4 until a person submits it again. `plans.commit_sha` is always the head the platform read (ADR-M40). [R049]
- G4 decisions are bound to the run proposal; G8 approvals to `evidence_packs.release_sha256` plus the merge, never to `content_sha256` (ADR-M33, ADR-M49). [R050]
- G7: reviews of the pushed commit are the approvals; `/approve G7` is refused; a request for changes is found by its receipt's event ID, never "the latest changes_requested review"; the API and CLI refuse `request_changes` at G7 (ADR-M41). [R051]
- Never issue a run twice. A kill stays a kill: every writer that ends a run uses `RunRepository.end`; never end a run with `transition` from `running` alone; never let a kill signal reach a later run (ADR-M42). [R052]
- Evaluation runs live in `evaluations`, `evaluation_runs` and the append-only `evaluation_run_results`, never in `runs`; their cost has `cost_records.evaluation_run_id` (never with an intent) and stays out of the intent cost reports; they use free runner slots only; codes and numbers, never a prompt, task text or diff (ADR-M81). Their scoring container is the sandbox image, two containers over one volume: install with the package proxy, then the diff and hidden tests with `NetworkMode: none` (guard `assertSafeScoringSpec`). The runner runs them on `sdlc-runner-eval` and writes no run event; the worker writes the result with the cost. The worker's `EvaluationLoop` is a plain loop (never a Temporal schedule); one workflow per run attempt (ID names the attempt); never prepare an attempt while the workflow of the earlier one lives. [R053]
- Evaluation plans (ADR-M82): only people with a role in `access.eval_roles` (never `viewer`) change or run them; a prompt variant is a file on the default branch, stored as path, commit and SHA-256, never its text; one open evaluation per plan; amounts change only by a new version, never below the month's spend. [R054]
- A project's evaluation tasks (ADR-M85): a task is its card on the default branch, stored as path, commit and SHA-256, never its content; its reviewer has a role in `access.eval_roles`, is never a producer of the intent, and the decision is bound to the card's SHA-256. [R134]
- Never offer an approval to a producer or to someone without the gate's role (`sdlc next`, the dashboard). [R055]
- Producers never decide: at G7 the creator, every run's `triggered_by`, the plan submitters and the commit authors; at G8 the creator, the people who allowed its runs and the plan submitters (ADR-M41, ADR-M49). Escalations are acknowledged and decided only by the owner role, the backup role or governance, never a producer (ADR-M28). [R056]
- A Git host or file that cannot be read makes the step wait; it never passes a gate (ADR-M39, ADR-M40). [R057]
- The platform never raises an intent's data class (ADR-M32). L1 runs never commit or push; their proposal is evidence, downloaded by a person (mode 600, never printed), and only that paused case takes a G4 rejection (ADR-M33 §2.9, ADR-M64). [R058]
- Pull request text on the public pilot is codes only; the GitHub logins a notice mentions are read when posting, never stored (ADR-M28, ADR-M30). [R060]

## Evidence, retention, reports
- Evidence is never overwritten (`If-None-Match: *`). Every stored item is re-checked (SHA-256, size) before a pack is built or a file is served: fail closed (ADR-M48). Processes that read client code from the evidence store never log or keep the bytes. [R069]
- An Evidence Pack holds codes, IDs, hashes, counts and references only (never a diff, spec, plan or review text); approvers' names only in the Markdown, every Markdown value escaped (ADR-M48). The purge identity `worker-purge` never reads (ADR-M51). [R070]
- Reports sum in SQL; money as decimal strings, token sums as digit strings, never floats; never a breakdown per person (ADR-M45, ADR-M47). `sdlc trial report` uses existing GET endpoints only, is built from named fields only and is checked by a strict schema before printing (ADR-M65). [R071]
- Retention purges never send the object-lock bypass; only the archive purge and the orphan sweep do. Nothing younger than 180 days is purged for retention, whatever the configuration (ADR-M51). The audit anchor bucket is COMPLIANCE; never log an anchor hash in a mismatch. [R072]
- Langfuse purge: select traces by run tags, check every trace's tags, never request `io`; no Langfuse step unless the key's project equals `SDLC_WORKER_LANGFUSE_PROJECT_ID` (ADR-M53). Never give the ClickHouse user `langfuse` access management (ADR-M63 §6). [R073]

## Database and audit
- Migrations are plain SQL (in TypeScript files under `migrations/`); never edit a merged one (a new one adds its SHA-256 to `migrations.lock.json`). Audit events are written only through `TenantScope.audit.append`. A new run event type, audit action or payload field is declared in `run-events/types.ts` / `audit/actions.ts` with a test. [R075]
