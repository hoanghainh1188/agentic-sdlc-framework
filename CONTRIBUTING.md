## 3. How to contribute

1. Branch from `main` (platform tasks: `task/<ID>-<short-name>`). Never rebase or force-push a branch under review; merge `main` into it.
2. Open a pull request with the template (AI disclosure, template T2). Put the task ID in the title.
3. Handbook changes: a separate pull request, approved by the handbook owner. Changes to **approved** documents in `design/`: a separate pull request with the reason; a new technical decision gets an ADR.
4. Record notable changes in [CHANGELOG.md](CHANGELOG.md).
5. Platform code: one task per session, plan first, tests for every acceptance criterion ([CLAUDE.md](CLAUDE.md), [platform/GETTING-STARTED.md](platform/GETTING-STARTED.md)). Before a pull request: `pnpm build && pnpm typecheck && pnpm lint && pnpm format:check && pnpm test`.

## 4. Conventions

**Writing**
- Plain English for non-native readers: the [writing style](handbook/00-introduction/06-writing-style.md). Short sentences, lists and tables; explain technical terms on first use.
- Source tags: **[Doc]** internal, **[External]** with a link, **[Proposal]** not yet backed by a source.
- Process documents use the 9-section structure (the [handbook contents](handbook/00-introduction/01-contents.md)).
- Only the codes of the [codes table](handbook/00-introduction/05-codes.md). Dates as `YYYY-MM-DD`.
- The handbook states its rules directly; it never cites the internal reference documents it was designed from.

**Handbook and platform stay consistent**
- The same codes and names everywhere: gates, autonomy levels, roles.
- A handbook process change that affects the platform: raise it in `design/QUESTIONS.md`, or update the design document first.
- A platform change people can see: update the matching handbook usage section in the same pull request.

**Code**
- Code, identifiers, commits and comments in English.
- Messages for people (CLI, comments on GitHub, Evidence Packs, the dashboard) go through the message catalog `@sdlc/messages`, English by default.
- No secrets in the repository; they live in OpenBao.

**Diagrams**
- Mermaid sources in `diagrams/src/`, SVG in `diagrams/svg/`. After editing a source, run `pnpm diagrams:render` and commit the SVG; CI checks that they match ([diagrams/README.md](diagrams/README.md)).
